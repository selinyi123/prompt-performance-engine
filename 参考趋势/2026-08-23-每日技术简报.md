# 每日技术简报｜2026-08-23

## 今日结论

今天最值得追踪的不是新模型，而是 Agent Runtime 的两个基础能力正在快速成熟：

1. **Runtime Event Log / durable authority**：执行日志不再只是观测数据，而开始成为 session、恢复、UI、上下文投影和审计的权威来源。
2. **Cost / cache / budget engineering**：缓存命中、cache write/read、token、tool-call 上限和 per-run spending 正逐渐成为 Agent 配置的一部分，而不是账单后的统计。

对 DPMS / PPE / KIS / ClipVault / Binggo 的共同启示是：下一阶段最值得共享的 primitive 不应继续扩成新的 Agent 协议，而应围绕 `ExecutionRecord / ContextRef / CostProfile / PolicyDecision / Evidence` 建模。

## 2. 今天最值得看的开源项目

### Apache Maka

GitHub： https://github.com/apache/maka

Maka 是今天优先级最高的架构参考之一。它的核心表述是：

> Log is the Runtime.

模型消息、Tool Call、Tool Result、permission decision、termination fact 都进入 Runtime Event Log；Session、UI、Context、Recovery 则是对该日志的投影。

值得借鉴的架构是：

```text
Runtime Host
   ↓
AgentRun
   ↓
Runtime Event Log   ← operational authority
   ↓
┌──────────┬──────────┬──────────┐
Session    UI       Context    Recovery
projection projection projection projection
```

Maka 还明确区分“Context”和“History”：Tool Result pruning、LLM compaction 可以改变下一次 inference 看见什么，但不会销毁执行证据。

这对 DPMS 和 KIS 都非常重要。

### Vercel Labs / fx

GitHub： https://github.com/vercel-labs/fx

`fx` 是 Zig 写的极小型 coding-agent harness，重点不是功能最多，而是 **embeddability**：CLI、本地/云模型、Skills、MCP、subagents，核心还能通过 WASM 嵌入其他宿主。

近期 PR 很有参考价值：permission mode 一致性、destructive action 退出 automatic review、one-off subagent retirement、connection/authentication ownership、persistent goal tracking、MCP startup timeout。

这些都说明生产 Agent Harness 的难点越来越集中在生命周期、权限、认证和恢复，而不是 ReAct loop。

### Windows AppContainer sandbox

Maka 0.1.11 加入 brokered Windows AppContainer sandbox，并强化 IPC ownership / ACL。多数 Agent sandbox 仍 Linux-first，这个方向对 Windows 本地产品很有参考价值。

## 3. 可借鉴的技术趋势与架构参考

### 趋势 A：Event Log 从 observability 变成 state authority

```text
append-only execution facts
        ↓
state projection
        ↓
UI / recovery / audit / context
```

收益包括 session 恢复、可审计 Tool side effect、UI 状态一致性，以及 context compaction 不删除 evidence。

但不能机械套用 event sourcing：外部不可逆 side effect 仍必须有 reconciliation 状态，不能因为日志里没有 success 就自动重试。

### 趋势 B：Context、History、Evidence 必须拆开

```text
Evidence → 永久执行事实
History  → 可浏览交互记录
Context  → 当前 inference 的有限工作集
```

### 趋势 C：Cost Profile 成为 Agent Configuration 一级维度

```text
ModelConfig
PromptRevision
ContextPolicy
CachePolicy
ToolPolicy
ExecutionBudget
```

并记录 success、quality、uncached input、cache write/read、output tokens、tool calls、wall time、cost。

## 4. 对五个项目的机会、风险和行动建议

### DPMS

建议新增只读 `ExecutionRecord` projection，复用现有 event/audit/evidence，不替换 real-run authority。外部平台动作继续由现有幂等、状态回读和 reconciliation 负责。

### Prompt Performance Engine

PPE 当前已有严格 benchmark、receipt verifier、Docker sandbox、replicate aggregation 和 authority gate。今天最值得新增的是 **Cost/Cache Experiment**：

```text
CostProfile
├ uncached_input_tokens
├ cache_write_tokens
├ cache_read_tokens
├ output_tokens
├ tool_calls
├ wall_time
└ estimated_cost
```

允许同一 benchmark 执行 `CachePolicy A/B`、`Budget Sweep`、`Context Layout Ablation`，最终输出 `quality × reliability × cost` Pareto frontier。

风险：provider 自报 usage 只能作为 provenance / diagnostic，不能被升级成独立 authority evidence。

### KIS

建议新增 `ContextSelection` artifact，绑定 task/session、card ids、content hashes、selection reason、token budget、trust state。这样可以区分“知识不存在”“检索没选中”“模型没正确使用已选知识”。

### ClipVault

不扩产品边界。继续 local-first，并预留 origin/source_app/content_hash/sensitivity/persistence_policy/session_ref。OTP、credential、secret 继续隔离于 history / knowledge path。

### Binggo

建议新增只读 `Run Trace` API，统一输出 state transition、action attempts、retry/backoff、risk decisions、external response class、evidence refs。MCP Agent 先做 inspect → explain → preview，不直接扩大写权限。

## 今日最终判断

今天最值得补的基础事实对象是：

```text
ExecutionRecord  → 这次执行发生了什么？
ContextSelection → 模型当时实际看到了什么？
CostProfile      → 为这次结果付出了多少资源？
```

如果这三个对象稳定下来，DPMS、PPE、KIS、Binggo 就能建立真正可复用的数据接口，同时仍保留各自的 authority boundary；ClipVault 则继续负责可信的本地上下文来源，而不是被强行改造成 Agent Runtime。
