## 2. 值得关注的开源项目或工具

### Paperclip
https://github.com/paperclipai/paperclip

Node.js + React 的多 Agent 管理面，可接 OpenClaw、Claude Code、Codex、Cursor、Bash、HTTP；核心不是聊天，而是 goals、org charts、budgets、governance、cost 与 heartbeat。

可复用对象：`Goal / AgentAssignment / Budget / Governance / Cost`。

### OpenClaw 2026.8.1
https://github.com/openclaw/openclaw/releases

新版本加入 **Secret egress host binding**：共享 secret 绑定精确 HTTPS destination host，未绑定目标在 plaintext egress 前 fail-closed；同时加入 SQLite snapshot create/list/verify/restore、plugin provenance warning、shared ingress lifecycle。

建议抽象：

```text
CredentialGrant {
  credential_ref
  principal
  destination_hosts[]
  scope
  expires_at
  approval
}
```

### Open Design 0.19.2
https://github.com/nexu-io/open-design/releases

Design System 3.0 已从 `DESIGN.md` 说明文件走向 design runtime：intent map + exact components + tokens + rules，并验证 component reuse、required states、token use、fallback behavior。

应借鉴的闭环：

```text
Design Contract → Generate → Launch → Validate → Evidence
```

## 3. 技术趋势与架构参考

### Agent 管理面组织化

```text
Goal
├ agents
├ budget
├ policy
├ progress
├ cost
└ evidence
```

管理面可以独立，但不能成为第二套 side-effect authority。

### Secret 权限进入 Egress Policy

传统 RBAC 只回答“谁能读 token”；下一阶段应回答“哪个 principal 可以在什么 task scope、多久、把哪个 credential 发往哪些 host”。

### Context engineering 转向 progressive disclosure

比无限增大 context 更稳的方式是：短 map + 可发现的结构化知识 + exact revision + trust state + mechanical validation。

### UI 设计契约必须可验证

`DESIGN.md` 只能减少歧义，不能证明实现正确。AI UI 应加入 visual/interaction test 和 contract validator。

## 4. 对项目的机会、风险和行动建议

### DPMS
保持现有“发现 → 判定 → 幂等动作 → 状态回读 → 留证”和 real-run gate。可以吸收 Paperclip 的 Goal/Assignment/Budget，但只作为 Control Surface。优先设计 `CredentialGrant v0.1`，让 Bilibili/Weibo credential 绑定 adapter、destination、scope、TTL。

### Prompt Performance Engine
当前 0.4.0 已有 deterministic audit、frontier schema、fail-closed preflight、budgeted host、offline replay 与 receipt verifier。下一步建议做 **Context Topology Ablation**：

```text
A giant instructions
B short map + structured docs
C retrieved relevant docs
```

比较 correctness / cost / context tokens / tool calls / failure class。

再加一类 policy benchmark：故意请求未授权 destination，验证系统是否真正 fail-closed，而不是模型“自觉不调用”。

### KIS
保持 canonical/derived 分离与人工确认。新增：

```text
ContextBundle
├ selected_cards
├ exact_revisions
├ trust_states
├ selection_reason
├ token_budget
└ consumer_session
```

目标不是提供更多知识，而是证明某次 Agent run 到底看到了什么。

### ClipVault
不建议扩功能。未来 OTP/secret transport 增加 destination-aware policy：source_device / destination_device / destination_app / TTL / one_shot / persistence=forbidden。

### Binggo
最适合验证小型 Agent Control Surface：Goal + Budget + inspect/explain/preview；写动作仍走现有 deterministic executor、风控和状态回读，不直接暴露 LLM 写权限。

## 最终判断

当前值得跨项目共享的 primitive 已收敛为：

```text
ExecutionRecord
ContextSelection
CostProfile
PolicyDecision
TrustContext
CredentialGrant
Evidence
```

今天新增的关键是 `CredentialGrant`：权限不只回答“Agent 能不能拿到秘密”，还必须回答“秘密能被发送到哪里、在什么任务里、多久、是否需要审批”。
